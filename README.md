# ai-future · 未来沙盘推演

[English version](README.en.md)

## 这是什么

这是一个用底层规律推演未来趋势、再从中筛选可下注商机的公开知识档案。核心问题不是「预测得像不像」，而是：当某种能力变得丰富，价值和约束会迁移到哪里？每个可用判断都必须留下推理链、时间窗、证伪条件、领先指标和置信度。

商机不是唯一终点。项目也记录**结构性后果**：人与人如何协作、社会关系如何重排、人与 AI 如何形成关系，以及权力、意义和制度可能怎样变化。能赚钱的方向进入商机候选；没有付费者但有完整证据链的后果，和商机平级保留；证据不足的才标为「仅图景」。

这里不把任何人的预测当作论据。先从供需、人性、历史、技术扩散和社会规律独立推演；若结论与常见共识重合，会明确标注「与共识一致」。

## 怎么读

- **只想进入故事**：从[推演链](docs/zh/chains/)开始。建议先读[生成变得便宜之后，什么反而买不到了](docs/zh/chains/10-generation-becomes-free.md)。
- **想看完整方法**：阅读[推演方法论](docs/zh/00-method.md)。
- **想看技术先后关系**：阅读[技术能力演进链](docs/zh/05-tech-sequence.md)。
- **想找可下注方向**：阅读[商机候选](docs/zh/40-opportunities.md)。
- **想复盘依据**：打开[判断台账](docs/zh/90-ledger.md)。

推演链负责让人读懂一条完整故事；技术顺序文件负责单独回答「什么先到，接着什么才可能」；台账负责保存判断的结构化元数据。叙事中引用 `J-NNN`，台账中记录它的时间窗、透镜、依赖和状态。更远的判断通过依赖链踩着近期判断向前，而不是被迫塞进严格的日历文件夹。

## 这套结构怎么读

近／中／远只是粗粒度容器，不是严格日历；精度由每条判断自己的时间窗承担。真正承担「序」的是卡片上的 `depends-on` 依赖链：更远的判断必须说明它踩着哪些近期或中期判断。

读者可以从一条远期判断开始，打开它的台账卡片，沿 `depends-on` 链逐个回溯上游，直到没有依赖；如果某条近期判断被证伪，就反向搜索哪些卡片依赖它，沿链逐层标记并重审受牵连的远期判断。这样，文档既保留可读的故事，也让推演的因果顺序可追踪。

## 判断编号 `J-NNN` 怎么用

每条判断分配全项目唯一的 `J-NNN` 编号（例如 `J-001`），中英文共用同一编号，编号不复用。阅读正文时，沿 `J-NNN` 到台账查看推理链、证伪条件、领先指标、置信度和 `depends-on` 依赖；某条判断被证伪时，其下游依赖必须重新审查，旧版本保留在 git 历史中。

时间层（近／中／远）是判断卡片上的粗粒度字段，不是正文目录。这样组织是因为远期判断必然依赖近期判断，且时间窗会随证据移动；按时间层拆正文会制造重复和腐烂。git commit 则记录判断如何随新证据演化。

## Git 记录纪律

中英两棵树必须在同一次 commit 内同步更新。每次提交必须说明**改了哪条判断（J-NNN）以及依据什么新证据**，禁止使用没有信息量的流水账标题（如 `update docs`）。判断状态变化（`ACTIVE`、`HIT`、`FALSIFIED`、`REVISED`）应单独记录，便于用 git 回看推演演化。

## 当前边界

首轮内容已有一条完整推演链和一条技术能力顺序链，但「全方位图景」仍未完成。组织与就业、注意力与信任、资本与权力、能源、生物医疗、教育、人与人协作、人与 AI 关系等维度，必须继续在台账的「显式缺口」中保留，不能把首轮成果冒充全景。
