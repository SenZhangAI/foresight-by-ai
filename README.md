# ai-future · 未来沙盘推演

[English version](README.en.md)

## 这是什么

这是一个用底层规律推演未来趋势、再从中筛选可下注商机的公开知识档案。核心问题不是「预测得像不像」，而是：当某种能力变得丰富，价值和约束会迁移到哪里？每个可用判断都必须留下推理链、时间窗、证伪条件、领先指标和置信度。

商机不是唯一终点。项目也记录**结构性后果**：人与人如何协作、社会关系如何重排、人与 AI 如何形成关系，以及权力、意义和制度可能怎样变化。能赚钱的方向进入商机候选；没有付费者但有完整证据链的后果，和商机平级保留；证据不足的才标为「仅图景」。

这里不把任何人的预测当作论据。先从供需、人性、历史、技术扩散和社会规律独立推演；若结论与常见共识重合，会明确标注「与共识一致」。

## 从哪读起

六条路径，按你想要的东西挑一条——每条都直接落在文件上，不需要先读完方法论。

- **想先确认基础打得牢不牢** → 读[历史回顾：什么才能成为整个社会的风气](docs/zh/01-retrospect.md)。它不预测任何事，只回看 1956–2020 年已经发生的成功与失败，从中提炼五道「普及闸」，并当场用它们判自己：可视电话 1964 年为什么不行、2020 年为什么三个月就普及；New Coke 五道闸全过却在 79 天后撤回；以及本仓库自己的 C1 开篇场景，被这套闸判为不过。
- **想被一个故事击中** → 读推演链。[C1 · 生成变得免费之后，什么反而买不到了](docs/zh/chains/10-generation-becomes-free.md) 从一个下午讲起：六十套方案摆在面前，市场负责人却什么也决定不了。[C2 · 当数据不再免费：现实信号如何变成合同资产](docs/zh/chains/20-real-signals-become-contracts.md) 接着回答，一次真实观测凭什么值钱、又凭什么能写进合同。[C3 · 电子落地：算力的瓶颈从芯片移到电网、土地与许可](docs/zh/chains/30-power-land-and-permits.md) 把链条推到地面：当模型可以租、芯片可以买，真正排不到的是一台尚未制造的变压器和一场必须召开的听证会。
- **想要全景** → 按时间层读三篇正文：[近期 2026–2028](docs/zh/10-near.md) → [中期 2029–2032](docs/zh/20-mid.md) → [远期 2033–2040](docs/zh/30-far.md)。每篇横向覆盖六个维度，从技术、内容、信任一路走到权力与意义。
- **想找可下注的方向** → 直接读[商机候选](docs/zh/40-opportunities.md)：四条通过硬约束闸门的候选（谁付钱、付多少、为什么是现在、最强反方），外加一份「现在能吃、但会被同一股力量吃掉」的窗口清单。
- **想检验我有没有胡说** → 打开[判断台账](docs/zh/90-ledger.md)。72 张判断卡片，每张写明推理链、时间窗、证伪条件、领先指标、置信度，以及它踩在哪几条上游判断之上。规则本身写在[推演方法论](docs/zh/00-method.md)，先看第 3 节的硬约束闸门。
- **想告诉我哪一条错了** → 读[如何反驳这里的判断](CONTRIBUTING.md)。它写明三件事：怎么用一条判断自己的证伪条件把它推翻、怎么补一个缺口维度、以及什么样的反对不会被采纳。

推演链和时间层正文讲的是同一批判断，切法不同：**链**沿一条因果线纵向讲到底，适合第一次阅读；**时间层正文**横向铺开同一时间窗里的多个维度，适合查全。两者都只在行文中内联 `J-NNN`，元数据一律退到台账。

技术能力的到达次序单独成篇：[技术能力演进链](docs/zh/05-tech-sequence.md) 只回答「什么先到、因此什么才成为可能」，不把社会后果提前写进去。

## 判断编号 `J-NNN` 怎么用

每条判断分配全项目唯一的 `J-NNN` 编号（例如 `J-001`），中英文共用同一编号，编号不复用；商机候选另用 `O-NNN`。

**正文里的每个编号都是链接**——点 [J-003](docs/zh/90-ledger.md#j-003--真正持久的稀缺是关于你的私有上下文的所有权与可用形态) 会直接落到台账里它那张卡片上，看到完整的推理链、证伪条件、领先指标、置信度和 `depends-on` 依赖。某条判断被证伪时，其下游依赖必须重新审查，旧版本保留在 git 历史中。

## 这套结构怎么读

近／中／远只是粗粒度容器，不是严格日历；精度由每条判断自己的时间窗承担。真正承担「序」的是卡片上的 `depends-on` 依赖链：更远的判断必须说明它踩着哪些近期或中期判断。

读者可以从一条远期判断开始，打开它的台账卡片，沿 `depends-on` 链逐个回溯上游，直到没有依赖；如果某条近期判断被证伪，就反向搜索哪些卡片依赖它，沿链逐层标记并重审受牵连的远期判断。这样，文档既保留可读的故事，也让推演的因果顺序可追踪。

**规则**：编号按写成的先后顺序分配，不预留、不复用；文件名用 `<编号×10>-<英文 slug>.md`，中英同名同号。**被预告但尚未写成的方向不给编号**，只在本表登记主题与当前落点。

为什么要有这张表：2026-09-19 之前，C1 链尾把「信任抵押化」预告成 C3，而实际写成 C3 文件的是电力与许可链——两条不相干的链撞在同一个号上。预告并非无迹可寻：它就写在 C1「九、这条链往下长出什么」一节里，写 C3 的人也确实读过 C1（C3 开篇拆的正是 C1 的默认前提）。真正缺的是**一个按编号去查的地方**——要撞上这个冲突，得先想到把每条链的链尾逐个翻一遍，而没有人会为了取一个编号做这件事。这张表就是那个地方。撞号已按「编号只指向一份真能点开的文件」收口：C3 归电力链，预告收回编号并登记在本表末行。

## Git 记录纪律

提交前先跑 `python3 scripts/check.py`（零依赖）：它检查全库内部链接与锚点、判断卡片必填字段、置信度白名单、依赖边三处一致、中英文件名与判断卡编号集合对等（不比对正文内容），以及本 README 的[推演链登记](#推演链登记)表与链文件是否互相覆盖、按标题引用某条链时标题是否出自该文件自己的 H1、「N 张判断卡片 / N 条独立推演链」两类计数是否等于仓库实际数量。它不能代替[发布前自检清单](docs/zh/90-ledger.md#十发布前自检清单)里的价值判断项，也不裁定任何一条判断的质量——绿灯不是「可以发布」的依据，只是「这几件机械不变量当前成立」。改过脚本要补跑 `--self-test`（全部负例必须仍以正确的检查名报警）。中英两棵树必须在同一次 commit 内同步更新。每次提交必须说明**改了哪条判断（J-NNN）以及依据什么新证据**，禁止使用没有信息量的流水账标题（如 `update docs`）。判断状态变化（`ACTIVE`、`HIT`、`FALSIFIED`、`REVISED`）应单独记录，便于用 git 回看推演演化。
