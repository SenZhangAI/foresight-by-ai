## 一、如何使用本台账

### 1. 判断卡片字段

一条可检验的判断必须填写以下字段。缺少任一项，只能标为「仅图景」，不得作为商机判断或摘要结论。

- **编号**：`J-NNN`，三位数字，全项目唯一；中英文共用，不复用已证伪或已修正的编号。
- **提出日期**：首次提出这条判断的日期，格式 `YYYY-MM-DD`。
- **一句话判断**：可在一口气内读完、能够被事实支持或推翻的命题。
- **推理链**：从底层规律与所选透镜出发，逐步写出中间环节，不以「某机构预测」代替论证。
- **时间窗**：判断预计发生或有效的起止区间；窗口结束仍未发生时，必须检查是否证伪或修正。
- **证伪条件**：一个具体、可观察、足以使作者承认判断错误的事件或数据结果。
- **领先指标**：结果出现前应先变化的可观测信号，并写明观察频率或来源。
- **置信度**：高／中／低；低置信度只能作为「仅图景」，不进入商机候选。
- **depends-on**：本判断依赖的其他 `J-NNN`；没有依赖写 `—`，不能用含糊的「见上文」代替。
- **状态**：`待定`（ACTIVE，等待窗口或证据）／`命中`（HIT，证据支持）／`证伪`（FALSIFIED，证伪条件触发）。如需改写，旧卡保留为「证伪」或转入修订记录，新卡取得新编号。

### 2. 填写示例（仅示例，不是项目正式判断）

> **示例卡片｜EXAMPLE-J-000（明确不计入正式编号）**
> - **编号**：EXAMPLE-J-000
> - **提出日期**：2026-09-18
> - **一句话判断**：在某个假想市场中，若可重复生成方案的单位成本下降一个数量级，单纯「多给方案」的服务价值会在三年内下降。
> - **推理链**：供给增加 → 方案边际成本下降 → 买方不再缺方案数量 → 价值转向取舍与验证；但这只是演示依赖写法，不代表本项目已采纳该命题。
> - **时间窗**：2026-09-18 至 2029-09-18。
> - **证伪条件**：到 2029-09-18，买方仍普遍按方案数量而非可验证结果支付溢价，且该现象不是由监管或供给受限造成。
> - **领先指标**：同类方案的单位生成成本与买方为人工筛选支付的中位数，每半年记录一次。
> - **置信度**：中（示例值）。
> - **depends-on**：—
> - **状态**：待定（示例值）。

正式卡片应复制上述字段，不应复制示例的编号；示例中的内容不会自动进入判断总表。

## 三、depends-on 依赖链

### 写法

使用逗号分隔的正式判断编号，例如：`depends-on: J-001, J-002`。依赖表示「若上游机制不成立，本判断必须重新审查」，不是表示两条判断同时发生，也不是引用文章位置。远期判断没有可列出的近期依赖时，应降级为「仅图景」，而不是假装独立成立。

当前链条：

```text
J-001（推理成本继续下降）
├── J-002（筛选是窗口）
│   └── J-003（私有上下文是较持久的稀缺）
├── J-004（可撤销行动基础设施）
└── J-005（不可重组输入升值）
    └── 待登记：数据合同化定价
        └── 待登记：信任抵押化（远期，可能仅图景）
```

### 上游被证伪后的操作步骤

1. 在台账中把上游卡片状态改为「证伪」，填写触发证伪条件、日期、证据链接，并保留原卡。
2. 沿每张卡片的 `depends-on` 反向查找直接下游；再逐层查找下游的下游，列出完整受牵连集合，不能只检查下一层。
3. 将受牵连卡片暂标为「待重审」（若当前格式只有三种状态，则在检查日志标注 `REVIEW_REQUIRED`，不得继续当作有效依据）。
4. 对每张受牵连卡片逐项重查推理链、时间窗、证伪条件与领先指标：区分「仍成立」「需要新编号修正」「也被证伪」。
5. 同一 commit 同步更新中文与英文台账、叙事引用和商机来源；commit message 写明上游 ID、触发证据和受影响 ID。
6. 在检查日志记录结论；不要删除旧卡，确保未来可以重建这次传播路径。

## 四、置信度变更史

置信度是可复盘的下注尺度，不是修辞。任何 `高／中／低` 的变化都应追加记录，而不是覆盖旧值。

**记录格式：**

```text
[YYYY-MM-DD] J-NNN: 旧置信度 → 新置信度
触发证据：可核查的观察、数据或推理变化（含链接或文件锚点）
影响：哪些中间步骤、证伪条件或 depends-on 解释随之变化
理由：为什么这条证据足以改变下注尺度，而不是只改变措辞
作者：<姓名或角色>
```

**示例（格式示例，不是正式变更）：**

```text
[2027-03-01] EXAMPLE-J-000: 中 → 低
触发证据：观察窗口内成本未下降，且出现可重复的替代机制（example/link）
影响：不再允许该示例进入商机候选
理由：原推理链依赖的成本下降前提被削弱
作者：example
```

## 五、到期检查流程

时间窗到期不是自动「命中」，而是强制复盘事件。到期日按以下顺序逐条处理：

1. 从总览筛出时间窗已结束的 `待定` 判断，先读其完整卡片和所有 `depends-on` 上游。
2. 按卡片原文逐字核对**证伪条件**：是否已经出现明确触发事件？有则记为「证伪」，写下日期、证据与观察范围。
3. 若证伪条件未触发，再核对**领先指标**：指标是否按预期先动、方向是否一致、数据是否缺失或被替代。指标支持但结果未完全出现时，仍保持「待定」，不得提前写「命中」。
4. 只有在时间窗内获得与判断明确一致、且没有触发证伪条件的证据时，才记为「命中」；说明支持证据和未覆盖的反例。
5. 若事实没有足够信息判定，不篡改卡片，记录为 `待定／证据不足`，并给出下一次检查日期与需补的领先指标。
6. 检查所有下游依赖：上游命中、证伪或修正都可能使下游进入重审；按第三节的步骤逐条处理。
7. 中英文台账在同一次 commit 更新，检查日志写入日期、逐条结果、证据锚点和下一步；commit message 写判断 ID 与新证据，禁止流水账。

检查记录格式：

| 日期 | 判断 ID | 证伪条件 | 领先指标 | 结果（命中／证伪／待定） | 证据 | 下次动作 |
|---|---|---|---|---|---|---|
| 2026-09-18 | J-001 等首轮判断 | 尚未到期 | 已登记，未到检查点 | 待定 | 首次建账 | 按各卡片窗口复查 |

## 九、技术能力演进链判断卡片

以下判断支撑 `05-tech-sequence.md` 的能力顺序。每条都保留五件套与最强反方；技术能力的出现不等于普遍采用。

### J-001 · 同等能力的单位推理成本继续下降

- **提出日期**：2026-09-18
- **一句话判断**：同等能力的单位推理成本到 2029 年底再降一个数量级。
- **推理链**：推理是可并行的确定性计算 → 累计产量与工程优化带来学习曲线 → 硬件能效、模型效率、调度复用三条相对独立的下降通道共同降低单位成本 → 同等能力可以被更频繁地调用。
- **时间窗**：2026-01 至 2029-12。
- **证伪条件**：出现连续 18 个月以上，达到同等能力的最低公开单位价格不降反升，且该上升不能由需求侧临时挤兑或一次性能源价格冲击解释。
- **领先指标**：达到固定基准分数所需的最低公开单位价格、单位算力能耗、开源模型追平当时最强闭源模型的滞后月数；每半年观察。
- **置信度**：高。
- **depends-on**：—。
- **最强反方**：能源、芯片供应或监管形成共同硬上限，使三条下降通道同时失效；若证伪条件触发，撤回本判断及其下游成本前提。
- **外部对照**：此处与共识一致；本判断的独立部分是三条下降通道的冗余推理，而不是引用外部预测。
- **状态**：待定。

### J-006 · 推理吞吐先于长程自主性

- **提出日期**：2026-09-18
- **一句话判断**：到 2028 年，单位任务可承受的并行推理次数将显著增加，生成—比较—修正会先于长程自主执行成为默认工作流。
- **推理链**：J-001 的单位成本下降 → 同一预算可运行更多候选路径 → 调度器可把简单步骤并行化并把困难步骤升级 → 工作流从单次回答变成候选搜索。
- **时间窗**：2026–2028。
- **证伪条件**：到 2028 年底，同等质量任务的主流系统仍只能承受单一路径，且成本下降没有转化为并行尝试。
- **领先指标**：公开系统的每任务采样数、端到端延迟与质量的联合曲线；每半年观察。
- **置信度**：高。
- **depends-on**：J-001。
- **最强反方**：能源、带宽或服务商排队把低成本收益锁在单次调用；若每任务并行度两年不升，本判断撤回。
- **外部对照**：此处与共识一致；分歧只在于将“吞吐先于自主性”作为顺序判断，而非功能清单。
- **状态**：待定。

### J-007 · 可接续上下文先于可靠长期记忆

- **提出日期**：2026-09-18
- **一句话判断**：2026–2029 年，任务级检索上下文会先成为跨轮次协作的普遍底座，而带来源、可修正的长期记忆随后才成熟。
- **推理链**：并行尝试增加状态量 → 单一上下文窗口无法容纳全部历史 → 任务、证据和未决问题必须被检索 → 可检索上下文先解决“找回来”，来源与版本再解决“是否可信”。
- **时间窗**：2026–2029。
- **证伪条件**：到 2029 年，主流长任务仍主要依靠无结构聊天回放，且检索上下文没有带来可测的续接收益。
- **领先指标**：长任务恢复成功率、检索命中率、上下文窗口外信息的引用比例；按季度观察。
- **置信度**：高。
- **depends-on**：J-006。
- **最强反方**：更长窗口与更强模型可能直接压过检索与记忆工程；若长窗口系统在长任务上持续优于结构化记忆，本判断降级。
- **外部对照**：此处与共识一致于“上下文重要”；分歧是把可接续上下文与可信长期记忆拆成先后两步。
- **状态**：待定。

### J-008 · 有来源的长期记忆成为可靠协作前提

- **提出日期**：2026-09-18
- **一句话判断**：2028–2031 年，要求来源、时间和置信边界的长期记忆会成为高价值连续协作的必要能力，而非聊天产品的附加功能。
- **推理链**：可接续上下文让历史可取回 → 历史中包含过时和互相矛盾的事实 → 需要事件来源、更新时间和撤回关系 → 只有可修正记忆才能支撑较长自主任务。
- **时间窗**：2028–2031。
- **证伪条件**：到 2031 年，高价值连续任务在没有来源、版本和撤回机制的记忆上仍能保持同等错误率与追责能力。
- **领先指标**：企业系统对记忆来源、时间戳和撤回接口的采购要求；事故复盘中由错误记忆导致的比例；每半年观察。
- **置信度**：中高。
- **depends-on**：J-007。
- **最强反方**：专用系统可能用隐式状态和人工复核掩盖记忆缺陷；若长期任务不要求追溯仍能稳定扩张，本判断撤回。
- **外部对照**：此处与共识一致于“AI memory”会增长；分歧在于把来源与可修正性视为可靠性的核心，而非单纯保留更多历史。
- **状态**：待定。

### J-009 · 受限工作流中的连续执行先成熟

- **提出日期**：2026-09-18
- **一句话判断**：2027–2030 年，权限有限、输入输出可检查的受限工作流会先实现稳定连续执行，开放世界自主性不会同步成熟。
- **推理链**：有来源记忆减少重复错误 → 封闭环境提供有限状态空间 → 权限与退出条件可预先写明 → 系统可连续完成多步动作并在失败处停止。
- **时间窗**：2027–2030。
- **证伪条件**：到 2030 年，开放世界任务的可靠性与受限工作流无显著差异，且权限边界与停止条件不再影响部署。
- **领先指标**：无人工接管完成的连续步骤数、受限环境的任务成功率、权限拒绝后的安全停止率；按季度观察。
- **置信度**：高。
- **depends-on**：J-008。
- **最强反方**：通用模型的世界建模能力突然跃迁，使封闭与开放环境差距消失；若开放任务在相同验证标准下追平受限任务，本判断撤回。
- **外部对照**：此处与共识一致于“agent 先从受限任务落地”；本判断的重点是可观测的执行边界，而非产品类别。
- **状态**：待定。

### J-010 · 长程自主执行晚于受限连续执行

- **提出日期**：2026-09-18
- **一句话判断**：2029–2033 年，跨较长时间、较少人工确认的自主执行才会在部分高价值场景达到可接受可靠性。
- **推理链**：受限工作流先积累状态和失败样本 → 长任务暴露更多未预见状态 → 系统需要在不确定时暂停并请求证据 → 可靠的长程执行依赖环境观测和评估回路，而非只依赖更长计划。
- **时间窗**：2029–2033。
- **证伪条件**：到 2033 年，长程任务仍只能靠逐步人工确认，或其事故率没有比 2029 年显著下降。
- **领先指标**：单次授权覆盖的平均动作跨度、长任务中主动暂停比例、人工接管与不可逆事故率；每半年观察。
- **置信度**：中。
- **depends-on**：J-009。
- **最强反方**：供应商可能用极强的专用流程把长任务切成大量隐形短任务；若无需扩大环境观测就能持续降低事故率，本判断需要重写。
- **外部对照**：此处与共识一致于“自主 agent 仍受可靠性限制”；分歧是给出先受限、后长程的机制顺序。
- **状态**：待定。

### J-011 · 跨媒介一致性先于长时连贯性

- **提出日期**：2026-09-18
- **一句话判断**：2027–2030 年，跨文字、图像、音频的局部角色与格式一致性会先成为可复用能力，跨长时段的因果连贯性随后出现。
- **推理链**：推理吞吐增加 → 可以对同一任务采样多个媒介版本 → 共享表示和约束检查先解决局部一致 → 长时连贯还需要持续状态与反复验证。
- **时间窗**：2027–2030。
- **证伪条件**：到 2030 年，长时段交互世界的因果、空间和动作连贯性已普遍稳定，而局部跨媒介一致性仍非默认能力。
- **领先指标**：跨媒介实体保持率、镜头或音色连续性、长时段状态漂移率；按季度观察。
- **置信度**：中高。
- **depends-on**：J-006, J-007, J-010。
- **最强反方**：统一世界模型可能同时解决跨媒介与跨时间一致性；若长时测试集与局部测试集同步跃迁，本判断撤回。
- **外部对照**：此处与共识一致于多模态扩展；分歧在于把“像”与“持续成立”明确拆开。
- **状态**：待定。

### J-012 · 跨时间连贯生成依赖状态与验证

- **提出日期**：2026-09-18
- **一句话判断**：2029–2034 年，长故事、持续交互环境和多轮设计中的跨时间连贯性，会在状态记忆和反复验证成熟后才达到生产级。
- **推理链**：局部跨媒介一致减少单帧错误 → 长任务仍会积累角色、空间和因果漂移 → 有来源记忆保存状态 → 自动反例与回放验证才允许持续修正。
- **时间窗**：2029–2034。
- **证伪条件**：到 2034 年，生产级长时生成仍不依赖状态追踪和回放验证，且漂移率已与短片段相同。
- **领先指标**：长时生成的状态漂移率、回放重现率、跨轮次修改的局部保持率；每半年观察。
- **置信度**：中。
- **depends-on**：J-008, J-011。
- **最强反方**：新型生成架构可能直接学习稳定世界状态，无需显式记忆与验证；若独立测试显示无需这些组件仍保持长时一致，本判断撤回。
- **外部对照**：此处与共识一致于长视频和交互内容更难；分歧在于把难点定位为状态与验证，而非单纯算力。
- **状态**：待定。

### J-013 · 可检查的工具调用先于开放环境行动

- **提出日期**：2026-09-18
- **一句话判断**：2027–2030 年，带参数、前置条件、权限和结果结构的工具调用会先普及，系统才会扩大到复杂环境中的连续行动。
- **推理链**：受限连续执行需要明确边界 → 自然语言工具调用难以检查 → typed 接口把动作和结果结构化 → 结构化调用先在少数工具上积累可靠性，再扩展工具面。
- **时间窗**：2027–2030。
- **证伪条件**：到 2030 年，高价值工具普遍接受无结构自然语言调用，且错误率与可检查接口无差异。
- **领先指标**：工具 schema 覆盖率、前置条件拒绝率、参数错误率、调用结果可回放比例；按季度观察。
- **置信度**：高。
- **depends-on**：J-009。
- **最强反方**：模型可通过自然语言自我纠错，接口结构化的收益很快被吸收；若无 schema 的工具在真实任务中持续追平，本判断降级。
- **外部对照**：此处与共识一致于工具调用会标准化；分歧在于将可检查性视为连续行动的先决条件。
- **状态**：待定。

### J-014 · 可演练环境晚于单工具接入

- **提出日期**：2026-09-18
- **一句话判断**：2028–2032 年，快照、影子运行、权限边界和回滚点组合成的可演练环境，会晚于单个工具接入但先于高价值自主行动普及。
- **推理链**：typed 工具能表达单个动作 → 多个动作会共享外部状态 → 真实状态不可随意试错 → 需要隔离、快照、影子运行和回滚来扩大尝试空间。
- **时间窗**：2028–2032。
- **证伪条件**：到 2032 年，高价值自主行动仍普遍直接写入真实环境，且隔离与回滚没有降低事故成本或采购门槛。
- **领先指标**：AI 工作流采购中影子环境和回滚条目；可恢复动作比例；自主行动保险或责任定价；每半年观察。
- **置信度**：中高。
- **depends-on**：J-010, J-013。
- **最强反方**：人工审批可用极低成本替代环境隔离；若人工逐条确认仍是主流且事故率足够低，本判断不应成为独立能力层。
- **外部对照**：此处与共识一致于沙箱和护栏重要；分歧是判断它们最终会成为环境基础设施，而不只是安全附加层。
- **状态**：待定。

### J-015 · 形式化验证先于开放世界评估

- **提出日期**：2026-09-18
- **一句话判断**：2026–2029 年，测试、schema、静态检查和反例搜索等形式化验证会先被生成系统内化，独立的现实结果评估随后成熟。
- **推理链**：并行生成增加候选数 → 可形式化性质能被程序快速判定 → 生成—测试—淘汰闭环降低错误输出 → 开放世界结果仍需等待观测与干预，不能由自评即时替代。
- **时间窗**：2026–2029。
- **证伪条件**：到 2029 年，开放世界结果评估已普遍可靠，而形式化测试仍未进入生成默认流程。
- **领先指标**：默认开启的自动测试比例、反例搜索覆盖率、schema 违规率、形式化验证对最终采纳率的影响；每季度观察。
- **置信度**：高。
- **depends-on**：J-006, J-009。
- **最强反方**：通用模型的自我评估可能直接跨越形式化与开放世界边界；若独立外部结果与模型自评在多领域长期高度一致，本判断撤回。
- **外部对照**：此处与共识一致于 AI coding 等领域自动测试增长；分歧在于明确其先后位置，而非把所有“评估”混为一类。
- **状态**：待定。

### J-016 · 开放世界评估是自主边界扩张的最后门槛

- **提出日期**：2026-09-18
- **一句话判断**：2029–2035 年，独立观测、因果干预和持续监控组成的开放世界评估，会成为长程自主行动扩大授权范围的最后技术门槛。
- **推理链**：形式化验证只能覆盖可预先写明的性质 → 长任务会遇到未建模状态和延迟副作用 → 外部观测与干预产生独立证据 → 持续监控把一次性测试变成运行时反馈 → 授权边界才可逐步扩大。
- **时间窗**：2029–2035。
- **证伪条件**：到 2035 年，长程自主系统在开放环境中无需独立观测、干预或持续监控，仍能达到与受限环境相当的事故率。
- **领先指标**：长任务中外部证据占比、因果实验触发率、运行时暂停与回滚率、授权范围随评估结果扩张的幅度；每半年观察。
- **置信度**：中。
- **depends-on**：J-010, J-012, J-014, J-015。
- **最强反方**：足够强的世界模型可能把开放环境压缩成可形式化模拟，独立评估不再是必要门槛；若真实任务中模拟预测长期达到独立观测水平，本判断撤回。
- **外部对照**：此处与共识一致于 agent 需要评估和监控；分歧在于把独立现实反馈视为最终扩权条件，而不是部署后的附加治理。
- **状态**：待定。
